Text extraction & cleaning
extract.pyraw → clean
# PDF → text, page by page
import pdfplumber
text = ""
with pdfplumber.open(f) as pdf:
    for page in pdf.pages:
        text += page.extract_text()

# cleanup pass
text = strip_headers_footers(text)
text = re.sub(r"\s+", " ", text)
text = fix_unicode(text)  # “smart” quotes etc.

DOCX uses python-docx; scanned PDFs need an OCR pass (Tesseract) first.

Why chunk at all?
  • Embedding models have a token limit — you cannot embed a 24-page document as one vector.
  • Retrieval precision — small chunks let the search return the exact paragraph that answers a question, not the whole file.
  • Overlap preserves context — repeating the last ~64 tokens at the start of the next chunk stops sentences being cut mid-thought.
Typical config: 512-token chunks with 64-token (≈12%) overlap. Smaller chunks = sharper retrieval but more vectors; larger chunks = more context but noisier matches.

Top-K retrieval ranking

Every stored chunk's vector is compared to the query vector with cosine similarity. The closer to 1.0, the more semantically aligned. The top 4 are kept — note that chunk #C-07 ranks high even though it never uses the word "leave".

RankChunkSourcePreviewCosineScore

Cosine similarity = (A · B) / (‖A‖ ‖B‖). Range −1…1; for normalized embeddings, effectively 0…1.

Cosine similarity, concretely
similaritypgvector SQL
-- pgvector: <=> is cosine distance
SELECT id, content,
       1 - (embedding <=> :q) AS score
FROM   chunks
ORDER BY embedding <=> :q   -- nearest first
LIMIT  4;                    -- top-K

The HNSW index turns this from an O(n) scan into an approximate-nearest-neighbour lookup in ~logarithmic time.

Vector comparison intuition

Two vectors pointing the same direction → angle ≈ 0° → cosine ≈ 1.0 → strong match. Direction encodes meaning; magnitude is ignored.

Small angle between query and C-03 → high similarity. C-31 points elsewhere → low.

03Prompt assembly

Augmentation — stitching context into the prompt

The retrieved chunks are not sent to the user — they are injected into the prompt as grounding context. This is the "augmented" in Retrieval-Augmented Generation. The structure is always: instructions, then evidence, then the question.

System prompt — the rulesYou are a helpful assistant. Answer the user's question using ONLY the context below. If the answer is not in the context, say you don't know. Cite the source document.

Token budget matters here. Context + question + system prompt must fit the model's window. In this run: ~640 context tokens + 95 system + 9 question = 744 input tokens. More chunks = more grounding but more cost and more chance of diluting relevance.
04Response generation

The LLM generates a grounded answer

The assembled prompt goes to the model. It reads the context, reasons over it, and produces tokens one at a time — streamed back through the server to the user's screen. Because the answer is anchored to retrieved text, it is far less likely to hallucinate.

Autoregressive generation
  • The model predicts the next token from the prompt + everything generated so far.
  • Each token is appended and fed back in — that loop is "autoregressive".
  • Streaming sends tokens as they're produced (Server-Sent Events), so the user sees words appear instead of waiting for the whole answer.
  • Grounding chunks keep the output faithful — the model paraphrases the evidence rather than inventing facts.

Embedding dimensions

Each chunk & query becomes a fixed-length vector of 1536 floats (text-embedding-3-small). Larger models (3-large) use 3072-d for finer meaning at higher storage cost. The number must match across documents and queries.

Where time goes

The LLM call dominates (~93% of query latency). Embedding + search together are under 110 ms. Optimisation effort belongs at the generation step — smaller models, prompt caching, or streaming for perceived speed.

Cost per query

Query embed (~$0.0000002) + generation (~$0.0003) ≈ $0.0003. Indexing is a one-time ~$0.0005 for all three documents. RAG is cheap to run; the expense is the LLM tokens, not the retrieval.
